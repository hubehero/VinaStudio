01 / the model

Vina 计算，VinaStudio 保存每一步。

Vina 的 Python API 是一组阻塞调用；命令行能完成一次对接，却不会替你管理结构、盒子、协议和失败原因。VinaStudio 把这套流程做成一个本地工作台，同时保持每一层的职责清楚。

对接分数不是实验自由能。 Vina、Vinardo 和 AutoDock4 都是在简化模型上打分；不同打分函数的数值不能直接比较。VinaStudio 把这一点写进界面和报告，而不是把它包装成一个确定结论。

结构转换会改变原子和氢的表示。 PDBQT 只保留重原子和极性氢，丢弃非极性氢是格式本身的行为。准备阶段会报告补了多少氢、是否生成了 3D 构象，以及检出多少可旋转键。

结果必须能回到协议。 作业保存实际使用的参数、输入哈希、引擎版本、种子和日志；关闭应用再打开，仍能解释“这个数是怎么来的”。

这些边界会直接写进界面：盒子空了会被拒绝，PDBQT 不会伪装成 PDB 渲染，外部地图缺失会直接说明。

02 / runtime shape

四层边界，一条本地回环。

Qt 主线程和 FastAPI 后台线程在同一个桌面进程里；对接跑到单独的 spawn 子进程。点击任意一层，看看它允许依赖什么、为什么这样切。

03 / preparation lab

输入如何变成可对接的 PDBQT。

受体和配体走的是两条不同的准备路径。切换查看实际发生的转换，以及报告里为什么会出现“原子数变少”。

PREP / INPUT
  1. 01

    读取与检查

    RDKit 读入 MOL/SDF/MOL2/PDB，检查显式氢、隐式氢、3D 坐标和可旋转键。

  2. 02

    补氢

    Chem.AddHs 补真实氢；Meeko 不接受只有隐式氢的分子。

  3. 03

    没有 3D 时生成构象

    ETKDG 嵌入，再用 MMFF94 优化。2D 输入不会直接进入对接。

  4. 04

    参数化与写出

    MoleculePreparation()(mol) 返回列表，取第一个 setup；PDBQTWriterLegacy.write_string() 返回三元组。

05 / job lifecycle

界面不等待 Vina，它订阅事件。

一次对接从 HTTP 请求变成子进程，再变成 WebSocket 事件。播放这条路径，看看“取消”为什么真的能停下计算。

  1. 01

    提交请求

    Vue 调 POST /api/docking/start，后端立即返回 job id。

    HTTP
  2. 02

    启动 worker

    JobManager 用 spawn 上下文创建子进程，并分配独立事件 Pipe。

    PROCESS
  3. 03

    执行计算

    worker 调 Vina/Meeko；stdout 重定向到作业日志。

    VINA
  4. 04

    回传事件

    结构化事件经 Pipe → EventHub → WebSocket 回到界面。

    WS
  5. 05

    完成或取消

    完成写 job.json 和工件；取消终止该 job 的所有 worker。

08 / boundaries

先看限制，再看结果。

这些限制决定哪些结果不能外推，也决定哪些工作流需要换引擎。

AD4

AutoDock4 需要外部地图

AutoDock4 需要 AutoGrid4 生成的亲和力地图；应用不捆绑 AutoGrid4，也不会假装现场生成。

PROGRESS

Vina 没有可靠的实时百分比

单次作业用阶段文本和活动条；只有批量/筛选的计数是真实进度。不要用定时器伪造百分比。

RENDER

PDBQT 不直接渲染

3Dmol 不解析 PDBQT，也不携带键级；姿态经 Meeko 转成 SDF 后再显示。
