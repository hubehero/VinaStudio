运行结构

关注进程和线程边界，而不是文件树。对接 worker 是单独 spawn 出来的。

  • 桌面进程one Python process
    • Qt 主线程窗口与界面
      • PySide6 外壳主窗口、原生菜单
      • QWebEngineViewVue 3 + 3Dmol.js
      • QWebChannel文件对话框、保存、打开目录
    • 后台线程本地 API
      • FastAPIREST /api/* · WebSocket /ws
      • JobManager提交、事件、取消、恢复
      • EventHub向 SPA 广播任务事件
  • spawn 子进程per task可以真正终止
    • worker.pystdout 解析、Pipe 事件
    • Vina / Meeko / RDKit对接与结构处理
  • 工作区persistent唯一持久化位置
    • jobs/作业产物、日志、job.json
    • projects/.vinaproj 项目文件
    • catalog.sqlite分子、Study、集合、筛选库

一次对接经过什么

这是顺序，不是目录树；它解释为什么界面不会被 Vina 阻塞。

  1. 界面提交：Vue 调 POST /api/docking/start，拿到 job id。
  2. 任务编排：JobManager 创建 spawn worker，分配独立 Pipe。
  3. 计算：worker 调 Vina/Meeko；stdout 重定向到作业日志。
  4. 事件回流：结构化事件经 Pipe → EventHub → WebSocket → 界面。
  5. 取消或完成：取消终止该 job 的所有 worker；完成写入 job.json 和工件。

Catalog 关系

分子是中心对象；Study、集合和筛选库通过成员表连接它。

  • 分子identity_key身份由结构决定，不由路径决定
    • 文件kind · path · sha256；一个分子可有多个文件
    • 别名 / 标签 / 来源名称、检索标签、来源与许可
    • Study 成员rolerole：受体 / 配体 / 辅因子；is_primary
    • 集合成员集合是可嵌套的组织树，不替代 Study
    • 筛选库成员引用分子，带 entry_index；筛选输入

怎么读

服务FastAPI + JobManager + EventHub
领域核心不依赖 Qt 或 FastAPI
